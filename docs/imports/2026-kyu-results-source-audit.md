## ไฟล์ธรรมศาสตร์ที่ถูกต้อง

ใช้ไฟล์ **2 จับคู่ธรรมศาสตร์** และอ่านผลจากชีต `Standings` เป็นหลัก ชีต `Pairings` และ `Results` ใช้ตรวจผลรายรอบ

ไม่ใช้ `Standings_Backup` เป็นผลสุดท้าย และไม่ใช้ไฟล์ใบประกาศเป็นแหล่งคะแนน เพราะไฟล์ใบประกาศมีชื่อ รุ่น และรางวัล แต่ไม่มีข้อมูลชนะ แพ้ SOS และผลรายรอบครบถ้วน

## หลักการนำเข้าคะแนนคิว

1. นำผลการแข่งขันเข้าตารางประวัติก่อน โดยยังไม่เปลี่ยน Kyu Rating
2. จับคู่นักกีฬาด้วย Athlete ID / GO ID / เลขที่คิว
3. หากมีเพียงชื่อ ให้ตัดคำนำหน้าและปรับช่องว่างเพื่อค้นหา แต่ต้องให้คนตรวจเมื่อพบชื่อซ้ำหรือสะกดต่างกัน
4. ตรวจระดับคิวล่าสุด ณ วันก่อนการแข่งขันจาก `1ทำเนียบคิวไทย`
5. เมื่อทราบระดับที่แน่นอนจึงกำหนดคะแนนเริ่มต้นและคำนวณผลตามลำดับวันแข่งขัน
6. รุ่น Dan เก็บประวัติการแข่งขันเท่านั้น ไม่สร้างรายการใน Kyu Rating ledger
7. Friendship และรุ่นที่ไม่บอกระดับชัดเจนเก็บประวัติได้ แต่พักการคำนวณคะแนนจนกว่าจะยืนยันระดับ
8. ข้อมูลย้อนหลังต้องคำนวณใหม่ตามเวลาและสร้าง revision ห้ามแก้ยอดคะแนนปัจจุบันโดยตรง

## ประเด็นคุณภาพข้อมูล

- ไฟล์ธรรมศาสตร์มีทั้ง `Standings`, `Standings_TEMP` และ `Standings_Backup`; ใช้ `Standings` เป็นผลสุดท้าย
- ไฟล์ธรรมศาสตร์มีบันทึกการแก้ผลย้อนหลัง จึงต้องเก็บ source row และ revision
- ไฟล์ซีคอนและมิงเกิ้ลระบุเป็นช่วงระดับ เช่น 5–6 Kyu ไม่ใช่ระดับรายบุคคล
- ไฟล์ลำพูนแบ่งเป็น Open, U10, U16 และ WOMEN จึงห้ามเดาระดับ Kyu/Dan จากชื่อรุ่น
- ไฟล์งานจริงอาจมีข้อมูลภายใน เช่น เบอร์โทร สถานะชำระเงิน หรือบัญชีกรรมการ ข้อมูลเหล่านี้ห้ามนำเข้า public profile
- รหัสผ่านหรือข้อมูลเข้าสู่ระบบที่พบในไฟล์เดิมต้องไม่คัดลอกเข้าฐานข้อมูลหรือ GitHub
