# จุดตรวจงานสมัครและโปรไฟล์

ข้อสรุปกับครูเล็ก 29 ตุลาคม 2569 บันทึกข้อกำหนด ไม่ใช่หลักฐานว่าพัฒนาฟังก์ชันเหล่านี้เสร็จแล้ว

## งานปัจจุบัน

ทำหน้ารับสมัครให้เสร็จทีละหน้าตามแบบที่เลือก ตรวจมือถือและคอม ทั้งโหมดสว่างและมืด อย่าข้ามไปพัฒนาสถิติย้อนหลังเพียงเพราะผู้ใช้เสนอแนวคิด

## ต้องตรวจตอนเชื่อมหน้าสมัครกับโปรไฟล์

- นักกีฬามี GO ID ถาวร การสมัครงานใหม่เป็นรายการใหม่ที่เชื่อมกับ ID เดิม ไม่สร้างนักกีฬาซ้ำ
- ก่อนอัปโหลดรูปจริง ใช้รูปตัวอย่างการ์ตูน 10 แบบ: หมากดำ 5 (ผมดำ 3 แดง 2) หมากขาว 5 (ผมทอง 3 น้ำเงิน 2) พื้นหลังตัดกับสีผมตามแบบล่าสุด
- สุ่มรูปแบบคงที่ตาม ID ให้คนเดียวกันใช้รูปเดียวกันทุกหน้า ไม่สุ่มใหม่ทุกครั้งที่เปิด
- ภาพที่อนุมัติล่าสุด: generated_images/exec-38c53b40-a1b3-46b5-aa63-7b03bbeb50ed.png ในพื้นที่งานรอบนี้ เป็นภาพรวม 10 แบบ ยังต้องจัดเตรียมไฟล์ใช้งานและเชื่อมโค้ด ห้ามสรุปว่าใส่เว็บแล้ว
- แสดงรูป ชื่อ และ GO ID ในโปรไฟล์ หน้าทบทวนใบสมัคร/สถานะ และรายชื่อที่ได้รับอนุญาตให้เผยแพร่ ใช้แหล่งรูปเดียวกันและตรวจสิทธิ์ก่อนเผยแพร่รูปจริง
- อัปโหลดรูปแล้วให้ลากจัดตำแหน่ง ครอป ซูม และดูตัวอย่างวงกลมขนาดเล็กก่อนยืนยัน ยกเลิกต้องคงรูปเดิม
- ข้อความแนะนำ: กรุณาใช้ภาพถ่ายจริงหน้าตรงของนักกีฬา เห็นใบหน้าชัดเจน และไม่มีสิ่งบดบังใบหน้า เพื่อให้ผู้จัดและกรรมการตรวจสอบตัวตนได้สะดวก กรุณาหลีกเลี่ยงภาพการ์ตูนหรือภาพบุคคลอื่นค่ะ
- แตะรูปหนึ่งครั้งเปิดภาพที่ครอปแล้วขนาดใหญ่ พร้อมชื่อและ GO ID ปิดแล้วอยู่ตำแหน่งเดิม ไม่เปิดหน้าจัดการบัญชีให้ผู้ชมทั่วไป
- เจ้าของบัญชีและแอดมินที่มีสิทธิ์แก้รูปหรือข้อมูลพื้นฐานได้ บันทึกประวัติการแก้ไข แอดมินช่วยกู้บัญชีด้วยการรีเซ็ต ไม่เปิดเผยรหัสผ่านเดิม
- ตรวจข้อมูลว่าง รูปโหลดไม่สำเร็จ รูปหน้าไกล ข้อมูลชื่อยาว และการเปลี่ยนรูปแล้วแสดงตรงกัน
- ก่อนแจ้งว่างานสมัครเสร็จ ให้รายงานแยกว่ารูปแบบใดออกแบบแล้ว แก้โค้ดแล้ว เผยแพร่แล้ว และทดสอบจริงแล้ว หากยังไม่ครบระบุเป็นงานค้าง

## งานระยะถัดไป ไม่เริ่มแทนงานรับสมัคร

ประวัติการแข่งขันรายรอบ: งาน รุ่น รอบ คู่แข่ง สีหมาก และผล/คะแนน เชื่อมกับ GO ID เดิม โดยใช้ผลที่ผู้จัดยืนยัน ข้อมูลเก่านำเข้าภายหลังเมื่อมีหลักฐานรายรอบ ไม่อนุมานจากรางวัล และไม่สร้างผลที่ขาดหาย

จังหวะกลับมาทำ: หลังเส้นทางสมัคร ชำระเงิน ตรวจสถานะ และโปรไฟล์พื้นฐานผ่านการตรวจแล้ว จึงทบทวนขอบเขตระบบคู่แข่งขัน/ผลแข่งกับผู้ใช้ก่อนขยายงาน
