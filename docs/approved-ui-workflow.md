# มาตรฐานหน้าตาและขั้นตอนทำงาน GO TOURNAMENT

ข้อกำหนดของครูเล็ก วันที่ 29 ตุลาคม 2569 ใช้กับการแก้ไขและสร้างหน้าต่อไปทุกหน้า

## แบบอ้างอิงที่อนุมัติ

ยึดหน้ารุ่น 1–2 คิวฉบับขอบกรมท่าและรายชื่อสมมติ 8 คนเป็นตัวอย่างจังหวะ ขนาด และความชัดเจน ภาพ 3992.jpg, 3993.jpg และ 3994.jpg ที่ผู้ใช้ส่งในวันที่นี้เป็นหลักฐานอ้างอิง ไม่ใช่ข้อกำหนดให้ทุกหน้ามีเนื้อหาเหมือนกัน

## หลักร่วมของทุกหน้า

- เว็บไซต์เดียวกันต้องมีภาษาภาพเดียวกัน: โลโก้ GO ฟอนต์ น้ำหนักหัวข้อ ปุ่ม กรอบ มุมโค้ง ช่องไฟ แท็บ ช่องค้นหา และสถานะ
- ใช้โค้ดส่วนประกอบและชุดสีร่วมที่มีอยู่ก่อนสร้างใหม่ ห้ามเปลี่ยนสไตล์ทั้งหน้าเพียงเพราะได้รับคำขอแก้เฉพาะจุด
- โหมดสว่างและมืดใช้ลำดับเนื้อหา ตำแหน่งปุ่ม ความหมาย และพฤติกรรมเดียวกัน ปรับสีตามธีม
- ปรับโครงหน้าได้ตามงาน เช่น สมัคร ชำระเงิน รายชื่อ จับคู่ ผลแข่ง อันดับ และโปรไฟล์ โดยรักษาความต่อเนื่องของการใช้งาน
- โหมดสว่าง: กรอบและเส้นแบ่งกรมท่า พื้นการ์ดขาว ช่องกรอกขาวหรือฟ้าอ่อน ตัวอักษรและ placeholder ดำหรือกรมท่าเข้ม หลีกเลี่ยงขอบและข้อความเทาจาง
- โหมดมืด: พื้นกรมท่า ตัวอักษรขาวหรือสีอ่อนที่อ่านชัด ขอบต้องมองเห็นได้ ใช้ทองเน้นการกระทำสำคัญอย่างสอดคล้องกัน
- ใช้สถานะพร้อมข้อความ ไม่สื่อความหมายด้วยสีอย่างเดียว โลโก้เว็บไซต์เป็น GO ไม่ใช้โลโก้สถาบันแทน

## มือถือและคอมต้องออกแบบร่วมกัน

- รักษาลำดับความสำคัญและสเกลที่รู้สึกเหมือนกัน ไม่ยืดหน้ามือถือเต็มจอคอม และไม่ย่อหน้าคอมทั้งหมดให้ลงมือถือ
- จำกัดความกว้างเนื้อหาตามงาน ใช้พื้นที่จอคอมเพิ่มคอลัมน์เฉพาะเมื่อช่วยอ่านจริง ตารางข้อมูลอาจกว้างกว่าการ์ดสมัครได้
- ตัวหนังสืออ่านได้โดยไม่ต้องซูม หัวข้อเด่นกว่ารายละเอียดอย่างพอดี ปุ่มกดสะดวก ช่องไฟไม่แน่นหรือเว้นเกินจำเป็น
- โปสเตอร์รักษาสัดส่วน เห็นภาพครบ ไม่ถูกบีบเป็นแถบ ไม่ยืด และไม่แย่งพื้นที่ข้อความ
- ชื่อยาว วันที่ สถาบัน และสถานะต้องไม่ล้นกรอบหรือแตกบรรทัดผิดจังหวะ ห้ามบังคับข้อความยาวลงคอลัมน์แคบ
- แถบปุ่มติดขอบจอต้องไม่บังรายการสุดท้ายและต้องเผื่อพื้นที่ปลอดภัยของอุปกรณ์

## ขั้นตอนก่อนแจ้งว่างานเสร็จ

1. อ่านข้อกำหนดนี้ ตรวจโค้ดเดิมและแบบล่าสุด ระบุหน้าที่ได้รับผลกระทบ
2. แก้ในส่วนประกอบหรือชุดสีร่วมให้ตรงขอบเขตคำขอ รักษาการเชื่อมหน้าและข้อมูลเดิม
3. ใช้ข้อมูลสมมติที่ระบุชัดเพื่อดูกรณีมีข้อมูลจริง โดยไม่ปะปนกับใบสมัครจริง ตรวจทั้งข้อมูลว่างและข้อความยาว
4. ตรวจอย่างน้อยจอมือถือ 360–390 พิกเซลและจอคอม 1280–1440 พิกเซลในทั้งสองธีม เพิ่มจอกลางเมื่อมีการเปลี่ยนคอลัมน์
5. ตรวจโปสเตอร์ ตัวอักษร ขอบ ช่องกรอก แท็บ ปุ่ม ตาราง และรายการท้ายหน้า รวมถึงการนำทางและค้นหาที่ได้รับผลกระทบ
6. รันการตรวจโค้ดหรือ build ที่เหมาะสม แก้ข้อผิดพลาดก่อนส่ง
7. แจ้งแยกว่าแก้โค้ดแล้ว เผยแพร่แล้ว และตรวจหน้าจอใดแล้ว หากยังตรวจไม่ได้ต้องบอกตรง ๆ

การเปลี่ยนมาตรฐานภาพรวมต้องมีคำขอจากครูเล็กหรือมีเหตุผลเฉพาะด้านการใช้งานที่อธิบายได้ ไม่ถือว่าการสร้างหน้าใหม่เป็นเหตุให้เริ่มออกแบบใหม่ทั้งหมด
